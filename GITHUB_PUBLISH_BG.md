# Публикуване на LEGO Collection Manager 2.1.6 за Windows

## Предварителна подготовка

1. Разархивирай пакета в отделна папка. **НЕ добавяй личната папка `data` към GitHub.**
2. В GitHub си създай акаунт и инсталирай GitHub Desktop.
3. Избери име на публично repository: `LEGO-Collection-Manager`.
4. В проекта има `updates.json` със стойност `YOUR_GITHUB_USERNAME/LEGO-Collection-Manager`. При GitHub Actions build тя **автоматично се заменя** с действителното име на хранилището за изтеглянията на потребителите. За ръчно билдване чрез BUILD_EXE.bat първо я замени ръчно с `ТВОЕТО_ИМЕ/LEGO-Collection-Manager`.
5. В GitHub Desktop: File > Add local repository > Choose папката `lego_216`. Ако предложи Create a repository, потвърди. Commit to main, след това Publish repository като **Public**. Потвърди, че папка `data` не присъства в променените файлове.

## Първа версия

6. В GitHub отвори repository > Actions > Windows release > Run workflow > version: `2.1.6` > Run workflow.
7. Изчакай зелено завършване. Ако GitHub откаже създаване на Release с 403, отвори Settings > Actions > General > Workflow permissions и разреши Read and write permissions, след което стартирай workflow отново. Ако вече има Release с таг v2.1.6, не създавай втори; изследвай грешката.
8. В repository > Releases ще има `LEGO-Collection-Manager-PORTABLE.zip` за нови потребители и `LEGO-Collection-Manager-UPDATE.zip` + `.sha256` за обновяване.
9. Изтегли PORTABLE ZIP на чист Windows компютър, разархивирай и стартирай `LEGO Collection Manager.exe`. Увери се, че няма вложена допълнителна папка и че `LEGO Updater.exe` е до основния EXE.

## Важно за обновленията

- Потребителят разархивира PORTABLE **само първия път** и запазва цялата програмна папка (не изолира само EXE).
- В приложението: Настройки > Провери за обновление. Ако се появи нова версия, отвори updater и след стартиране на самото инсталиране **затвори основния LEGO Collection Manager**, за да може файловете да се подменят. Updater-ът изчаква затваряне до около минута.
- Самият `LEGO Updater.exe` няма да се подменя чрез текущите UPDATE ZIP файлове; ако поправяме updater-а, ще трябва отделна стъпка за обновяването му.
- За бъдеща версия: обнови кода в хранилището, Commit + Push, после Actions > Run workflow с нов номер, например `2.1.7`. Номерът трябва да е по-висок и новият Release да има всички 3 файла.
- Не премествай и не изтривай `data`. Тя се намира до EXE и съдържа база, снимки, настройки и архиви.
- На всеки компютър колекцията е самостоятелна. GitHub не получава снимките/базата/API ключа.
- Безплатният план на GitHub има приложими лимити за Actions; следи ги в профила си.

## Сигурност и реални ограничения

- SHA-256 проверката засича повреден/променен ZIP спрямо публикувания checksum, но сама по себе си **не е цифров подпис**. Преди широко публично разпространение направете тест на цялата верига и помислете за подписване на изпълнимия файл.
- Не качвай чужди търговски марки, изображения или лога без право за разпространение. Проверявай условията на Rebrickable и правообладателите.
- Кодът е проверен статично; в тази среда не е извършен реален Windows EXE или GitHub Actions build. Не обещаваме, че тези стъпки вече са изпълнени.
